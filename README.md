# PDF 工作台(pdf-workbench)

> 這是一個**單一 HTML 檔、完全離線**的 PDF 編輯工具。本文件包含功能說明、架構與建置方式;原始碼在 `src/`、`build.py`,開發路線圖見 [`docs/ROADMAP.md`](docs/ROADMAP.md)。

**下載最新版**:<https://tony028p.github.io/pdf-workbench/>(下載後用瀏覽器開啟即可,也可以直接在瀏覽器開啟;各版本見 [Releases](https://github.com/tony028p/pdf-workbench/releases))
- 精簡版(約 7 MB):大多數人用這個就夠了
- 含文字辨識(OCR)的完整版(約 29 MB)
- 或是精簡版 + OCR 套件檔(約 17 MB,需要辨識時在「文字辨識」載入)

---

## 1. 這是什麼

- 使用者用瀏覽器雙擊 `pdf-workbench.html` 就能用,**不需要網路、不需要伺服器、不上傳任何資料**。
- 成品約 2.9 MB,因為把以下東西全部內嵌進同一個 HTML:
  - `pdf-lib`(寫出/編輯 PDF)
  - `pdf.js` v3.11.174 UMD 版(顯示頁面、轉圖片)
  - pdf.js worker(以 base64 內嵌,執行時轉成 Blob URL)
  - 56 個 CJK CMap(`.bcmap`,以 base64 內嵌),讓使用非嵌入式繁/簡中文字型的舊 PDF 也能離線正確顯示
- 完整版(`pdf-workbench-ocr.html`,約 29 MB)另外內嵌文字辨識引擎:onnxruntime-web(WASM)與 PaddleOCR PP-OCRv5 mobile 模型,同樣完全離線。
- 介面語言:繁體中文。

## 2. 功能清單

**頁面管理**
- 一次加入多個 PDF 或圖片(png/jpg/gif/webp/bmp),依序自動合併;圖片會轉成 A4 內的一頁。
- 左側縮圖列:單選、Ctrl/⌘ 多選、Shift 範圍選、拖曳排序(可拖曳多選群組)。
- 頁面操作:左轉、右轉、複製、前移、後移、刪除(作用於選取頁;沒選取則作用於目前頁)。
- 復原/重做(Ctrl+Z、Ctrl+Y / Ctrl+Shift+Z),最多 120 步。
- 縮放:按鈕、Ctrl+滾輪、符合寬度;頁碼跳轉;拖放檔案到視窗即可加入。
- **有密碼的 PDF**(`core/crypto.js`、`core/decrypt.js`):開啟時詢問密碼(開啟密碼或擁有者密碼皆可,輸入錯誤可重試);只有使用限制(禁止列印、複製…)、不需開啟密碼的檔案直接開啟,並提醒確認你有權處理這份文件。支援 PDF 標準加密的全部演算法:RC4 40/128 位元、AES-128、AES-256(含 Acrobat 9 的舊版 AES-256),以及打包在物件串流(object stream)中的物件;中文密碼可用。解密完全在瀏覽器內進行,密碼不會傳送或儲存;開啟後就是一般 PDF,**匯出的檔案不再加密**。
- 大檔優化:主編輯區用 IntersectionObserver 懶載入,離開視野的頁面釋放 canvas(200 頁測試僅同時保留約 2–3 個 canvas)。
- **觸控裝置**(平板、手機):縮圖**長按約 0.4 秒後拖曳**即可排序(輕觸選取、直接滑動是捲動,拖到邊緣自動捲動);用「選取」工具時手指滑動可以捲動頁面,按在標註上則移動或縮放標註;畫筆、直線、螢光筆、塗黑、裁切等工具用手指直接畫。

**加入內容**
- 文字:支援中文與多行,黑體/明體/楷體、大小、粗體、顏色;雙擊可再編輯;可拖曳、右下角縮放。
  - **「黑體」寫成真正的文字**(`core/fonts.js`):內嵌思源黑體 Noto Sans TC Regular(約 1.2 萬字,SIL OFL 1.1),畫面上用同一個字型顯示,匯出時只嵌入用到的字形(子集,通常幾十 KB),可以選取、搜尋、複製;位置與畫面上一致(含旋轉的頁面)。粗體用描邊加粗。字型沒有的罕用字、明體與楷體仍以圖片嵌入。表單的中文值也用這個字型寫成真文字。
- **改字**(`ui/retext.js`、`edit/retext.js`):用「改字」工具點一下頁面上原有的文字(滑過時會框出範圍),或拖曳框選其中幾個字(可跨行),輸入新的內容;留空就是刪除。字級、字型(明體/楷體/黑體、粗體)與顏色預設跟原文字一樣,底色從頁面取色,新文字的基線對齊原文字;產生「改字框」與新的文字標註兩個標註,一次復原。
  - **原文字從檔案刪除,不只是蓋住**:匯出 PDF 時解析內容串流,字形中心在改字框內的字從文字指令中刪掉,同一行的其他字換成等寬的位移,位置完全不變(含字距、水平縮放、TJ 位移、CID 中文字型、表單 XObject 裡的文字;同一個表單在其他頁照常保留)。每個字的寬度直接用 pdf.js 解析好的字形(和畫面顯示一致),並用字碼核對與內容串流一一對應;對不上或無法處理(例如直書)時那一頁只用底色蓋住,匯出完成訊息會列出頁碼。
  - 擷取文字、選取文字、Word/Markdown/Excel、可搜尋 PDF 的隱形文字層都不再包含改字框內的原文字(片段只有一部分在框內時切開,其餘保留)。改字框可以用選取工具移動、縮放、改底色或刪除(刪除就恢復原文字)。
  - 掃描頁:辨識過的字一樣可以點選修改;沒有文字的地方可以直接框選範圍蓋掉重寫。
- 圖片:選檔後點頁面放置。
- 簽名:手寫板(黑/藍/紅墨色),或上傳簽名圖片(自動去白底並裁邊);可重用上次簽名。

**標註**
- 畫筆、直線(Shift 鎖定 45° 倍數角度)、螢光筆(multiply 混色、半透明)、塗黑。
- **裁切**:用「裁切」工具框選要保留的範圍,範圍外變暗;畫好後可拖曳邊線移動、右下角調整大小、Delete 刪除,或「套用到所有頁面」。每頁一個裁切框,可復原。匯出 PDF 時設成頁面的 CropBox(閱讀程式只顯示這個範圍,旋轉的頁面也正確),匯出圖片時只輸出這個範圍;真塗黑的頁面同樣套用。
- 選取工具可移動、縮放(文字/圖片/矩形類)、Delete 刪除;顏色與粗細可即時套用到已選標註。

**浮水印與頁碼**
- 文字浮水印:文字、大小、顏色、透明度、角度(水平/斜 45°/反向斜/直向)、可重複平鋪。
- 頁碼:5 種格式(含「第 N 頁,共 M 頁」)、6 個位置、大小、顏色、邊距、起始頁碼。
- 設定即時預覽在編輯區,匯出時套用到所有頁面。
- **移除 PDF 原有的浮水印**(`edit/content-stream.js`、`edit/unwatermark.js`):在「浮水印與頁碼」按「偵測並移除原有的浮水印」,列出找到的項目(例如「文字『CONFIDENTIAL』(斜 45°、半透明、淺色) 第 1–3 頁」),勾選後套用,編輯畫面立即更新;取消勾選再套用即可恢復。
  - 可以可靠辨認:浮水印註解(`/Subtype /Watermark`)、標記為浮水印的內容(Adobe Acrobat 等加入的 `/Artifact <</Subtype /Watermark>>`、名稱含 Watermark/浮水印的選用內容群組、PieceInfo 標示為浮水印的表單物件)。
  - 用規則判斷(使用者確認後才移除):旋轉(非 90° 倍數)或半透明、而且淺色/大字/半透明的文字;旋轉且半透明、或半透明且面積大的圖片(本工具加的浮水印也屬這類);內容全是上述文字或圖片的表單物件。
  - 做法是解析頁面的內容串流,刪掉畫浮水印的指令、註解與不再使用的圖片/表單資源,**匯出的檔案裡完全沒有浮水印物件**(不是蓋白框)。原始檔保留在記憶體中,可隨時恢復。

**填寫表單**(`edit/forms.js`、`ui/form-layer.js`)
- 「填寫表單」工具:PDF 裡的表單欄位(文字框、多行文字、勾選框、單選、下拉與清單選單)直接變成可以輸入的框,唯讀欄位不能修改;同一個欄位出現在好幾個地方時一起更新。
- 填好的值用 pdf-lib 寫進 PDF(`/V`)並替換來源檔,畫面、縮圖、匯出、真塗黑都直接用填好的檔案。外觀:只有 Latin-1 字元時用 Helvetica 產生(可選取);含中文時畫成圖片當外觀(離線沒有可內嵌的中文字型),值仍以文字存在欄位裡,其他程式重新編輯時會用自己的字型。
- 匯出 PDF 時保留可填寫的欄位(重建 `/AcroForm`,只包含實際在輸出頁面上的欄位);也可以選「表單欄位轉成一般內容」,把目前的外觀畫進頁面並移除欄位。
- 真塗黑的頁面整頁轉成影像,那一頁的欄位(含值)不會留在檔案裡。

**擷取文字**
- 擷取全部或選取頁面的文字,可「複製全部」或下載 TXT(UTF-8 含 BOM,Windows 記事本開啟不會亂碼)。
- 版面分析:依文字方向分行(支援內建 `/Rotate` 與旋轉過的頁面)、偵測多欄與跨欄標題、依行距/縮排/句尾標點/清單符號分段;中日韓文字換行直接相接、英文補空格、行尾連字號接回;去除假粗體的重複文字。
- **塗黑範圍內的文字整段排除**(寧可多刪,不可外洩);被之後畫的塗黑框蓋住的文字標註也不輸出。
- 自己加入的文字標註可選擇一併輸出;沒有文字層的掃描頁、疑似亂碼的頁面會顯示提醒。
- 原始文字依「來源檔:頁索引」快取在 `textCache`,不放進 `S.pages`(undo 快照不會變大)。
- **顯示文字層**(`ui/text-view.js`,工具列上方的「顯示文字層」按鈕):在頁面上框出可以選取、搜尋的文字,滑鼠停在框上顯示內容。藍框是 PDF 本身的文字、綠框是文字辨識的結果、紅框疑似亂碼(私用區字元或替換字元超過三成);目前頁面沒有文字時提示可以先用「文字辨識」。和擷取文字相同的內容(塗黑與改字框內的字不算),只在畫面上顯示、不會匯出,只讀取看得到的頁面。
- **外觀相同的部首字元換回一般的字**:Chrome 等程式用 Noto CJK 字型輸出的 PDF,「文、一、日、月、民、長」常被對到康熙部首或部首補充字元(`⽂` U+2F42、`⺠` U+2EA0),看起來一樣卻搜尋不到;擷取、選取文字、Word/Markdown/Excel 都換回一般的字(康熙部首用 NFKC,部首補充依 Noto Sans CJK TC 共用同一字形的字對照)。
- **選取文字工具**:在頁面圖上疊一層透明文字(`.tl`,放在隨頁面旋轉的 `.pvin` 裡),可用滑鼠框選、Ctrl+C 複製;複製時同樣經過版面分析(接回連字號、中文換行不加空格)。只在工具啟用時建立,縮放、塗黑或復原/重做改變時重建;塗黑範圍內的文字不會放進去。拖過行尾時用 pdf.js 的 end-of-content 做法,讓選取停在最後選到的字。

**文字辨識(OCR,只有完整版)**(`ocr/ocr.js`、`src/ocr/worker.js`;引擎比較見 [`docs/OCR_SPIKE.md`](docs/OCR_SPIKE.md))
- 範圍:自動(只處理沒有文字層的掃描頁與文字亂碼的頁面)/ 全部 / 選取頁;顯示進度,可隨時取消(已完成的頁面保留)。
- 在背景 Web Worker 執行(畫面不會卡住):以 300 dpi、含使用者旋轉渲染頁面(橫躺的掃描轉正後再辨識),PaddleOCR 偵測文字行 → 依旋轉外框裁切轉正 → 辨識;每個字的位置由 CTC 解碼的時間步推算,再對齊到字與字之間的實際空白。
- 數字:數字之間的全形逗號、句點轉成千分位與小數點(`1，284．6` → `1,284.6`),全形數字轉半形。
- **標出信心較低的字詞**:辨識完成後,信心低於 85% 的字詞在頁面上用橘色虛線框標出(滑鼠停在框上顯示信心與辨識結果),完成訊息顯示數量,方便人工核對;只在畫面上顯示,不會匯出,可在辨識視窗關閉。實測清楚的字信心幾乎都在 90% 以上,認錯或殘缺的字多半低於 70%。
- **簡轉繁**(`text/s2t.js`,預設開啟,可在辨識視窗取消):辨識出的簡體字轉成台灣用字(这→這、为→為)。對照表由 `build.py` 從 OpenCC 字典(`opencc-data`,Apache-2.0)產生,只收繁體裡不會出現的簡體字;「后、里、台、干、面、么」這類繁體也用的字不轉,原本正確的繁體不會被改壞;一對多的字依詞組決定(头发→頭髮、发展→發展)。轉換前後字數相同,每個字的位置框不變。
- 結果換回基準座標,變成和 PDF 文字層相同的片段,存在 `ocrCache`(不放進 `S.pages`,undo 不受影響;依「來源檔:頁索引」存放,旋轉、複製、刪除再復原都不需要重新辨識)。擷取文字、選取文字、匯出 Word/Markdown/HTML 都直接使用辨識結果(掃描頁在 Word「可編輯」模式變成真正的段落);**塗黑範圍內的辨識文字同樣排除**。
- 引擎與模型以 gzip + base64 內嵌,第一次辨識時才解碼。
- **精簡版載入 OCR 套件**:`build.py --ocr` 同時產生 `pdf-workbench-ocr-pack.bin`(約 17 MB,內容與完整版內嵌的相同,隨 Release 發佈)。精簡版按「文字辨識」時請使用者選擇這個檔案,在本機讀取後就能辨識(不上傳、不連網);檔頭記錄 OCR worker 的版本,不同版本的套件會被拒絕並說明原因。載入只在這個分頁有效,重新開啟要再載入一次。
- **可搜尋 PDF**(`export/ocr-layer.js`):匯出 PDF 時,辨識過的掃描頁保留原本影像,疊上隱形文字層(text render mode 3),在任何 PDF 閱讀器都能搜尋、選取、複製。字型採 Tesseract 的 GlyphLessFont 做法(Type0 / Identity-H、所有字碼對到同一個空白字形、ToUnicode 直接對應 UTF-16),不需要內嵌中文字型,整份只多約 1 KB。每段文字用 `Tm` 放到原位(含 `/Rotate` 與使用者旋轉)、`Tz` 水平縮放對齊原圖字寬;同一行不需要空格的字詞合成一段,讀取程式才不會在中文字之間補空格。塗黑範圍內的字詞不寫入(真塗黑轉成影像的頁面也加上文字層);原本就有文字的頁面不重複疊加。可在匯出視窗取消勾選。

**匯出**
- PDF:合併成單一檔 / 每頁一個檔(ZIP) / 依範圍拆分如 `1-3, 5, 8-10`(每段一個檔,ZIP)。
  - 複製頁面時,指向其他頁面的參照(連結目的地、表單欄位)只會對到這次有輸出的頁面;連到沒有輸出或真塗黑頁面的連結會移除,**那些頁面的原始內容不會被帶進檔案**。存檔前刪除所有走不到的物件。
- **壓縮 PDF**(`export/compress.js`):匯出 PDF 時選擇高品質(220 dpi)/ 標準(150 dpi)/ 最小(96 dpi)。走一遍每頁與表單物件的內容串流,依圖片實際顯示的大小算出解析度,超過目標 1.2 倍才縮小並重新存成 JPEG(同一張圖畫好幾次時依最大的那次);原本就是 JPEG 的圖片重新壓縮後小 30% 以上也替換;有透明遮罩的圖片只縮小顏色部分。另外無損地拿掉串流外層的 ASCII85/ASCIIHex 編碼。文字、向量圖、字型不變;真塗黑的整頁影像一併壓縮;完成時顯示壓縮前後的大小。
- **匯出 PDF 時加上密碼**(`export/encrypt.js`):AES-256(PDF 2.0 標準加密 V5/R6,Acrobat X 以後的閱讀程式與 Chrome 都支援)。檔案金鑰隨機產生,每個串流與字串(含文件資訊)都加密,用瀏覽器內建的 Web Crypto 計算。可另設擁有者密碼,並選擇是否允許列印、複製內容、修改;沒有擁有者密碼時不限制權限。拆分匯出時每個檔案都加密。密碼只用在這次匯出,不保存,關閉對話框後清空。
- 圖片:PNG 或 JPG,每頁一張(多張自動打包 ZIP),解析度 100/150/220/300 dpi。
- **Word(.docx)**(`export/docx.js`,自己產生 OOXML,用既有的 `makeZip` 打包,不需額外函式庫):
  - 可編輯:沿用文字擷取的版面分析重排成段落;依字級判斷標題 1–3(內文字級每個來源檔各自計算)、清單縮排、置中段落;保留粗體/斜體/字級,字型對應為新細明體/微軟正黑體/標楷體(中文)與 Times New Roman/Arial(英文);圖片裁切後放在原位附近(靠左或置中);用繪圖指令畫的向量圖(折線圖、散佈圖等:含曲線、斜線或長折線的圖形群)也裁切成圖片,圖上的標籤與座標軸文字只留在圖裡、不散成段落;符號字型(Wingdings、Symbol…)的常見符號轉成 Unicode(▲▼●•…);重複的頁首頁尾與頁碼移出內文,改用 Word 頁尾的自動頁碼;掃描頁整頁當成圖片;可選每頁 PDF 是否從新頁開始(每頁一節,保留頁面大小與方向)。
  - 保留外觀:每頁整頁轉成一張圖(一律真塗黑)。
- **表格偵測**(`text/tables.js`,擷取文字、選取文字、Word、Markdown、HTML 共用):
  - 有框線:從繪圖指令取出水平/垂直線段(含細長填色矩形,以及每格各自填色的矩形四邊),交錯成格線;缺少的內框線視為合併儲存格。大部分格子是空的格線(例如圖表)不算表格。格子裡刻意逐行列出的項目(下一行的第一個字放得進上一行卻換行)各自成段;儲存格底色保留到 Word/HTML(深色底用白字)。
  - 無框線:連續 3 列以上都分成幾段隔得很開、上下對齊的文字(例如目錄的標題與頁碼);至少要有一欄是短內容,避免把報紙式分欄誤判成表格。右緣整齊的欄靠右對齊,子項目保留縮排。
  - 輸出:擷取文字為 Tab 分隔的列(可直接貼到 Excel);Word 為真正的表格(有框線才畫框線,合併儲存格用 gridSpan/vMerge);Markdown 為表格語法;HTML 為 `<table>`。
- **Excel(.xlsx,只匯出表格)**(`export/xlsx.js`,自己產生 SpreadsheetML,用 `makeZip` 打包):每個偵測到的表格一個工作表(「第 3 頁」「第 3 頁 表2」)。數字存成真正的數值並保留原本的顯示格式(千分位、小數位數、百分比、負號與括號負數、正號、NT$/US$/$ 等貨幣符號),可以直接加總計算;開頭是 0 的代號、日期、電話維持文字。合併儲存格、粗體、底色(深色底白字)、對齊、欄寬、格內換行一併保留;表格來自表格偵測(含 OCR 結果),塗黑範圍排除。
- **Markdown(.md)/ HTML(.html)**(`export/markdown.js`):與 Word 共用文件模型(`export/doc-model.js`:段落、標題、清單、圖片、頁首頁尾移除、塗黑規則)。Markdown 用 `#` 標題、`-`/`1.` 清單、`**`/`*` 粗斜體,PDF 內容中的 Markdown 特殊字元會跳脫;有圖片時打包成 ZIP(`.md` + `images/`)。HTML 為單一檔案、圖片以 data URI 內嵌,所有文字都經過跳脫(PDF 內容不會變成 HTML 標記或指令碼)。可選頁與頁之間加分隔線。
  - 塗黑:文字走擷取文字的排除規則;圖片一律從「依序燒入所有標註(含塗黑框)」的頁面圖裁切,不直接取用 PDF 內的圖片物件。
- 範圍:全部頁面或僅選取頁面。
- 真塗黑:有塗黑標註的頁面,匯出時整頁轉成 JPEG 影像後才燒入黑塊,底層文字會被移除(可在匯出視窗取消)。最後一個塗黑框以前加的標註(文字、圖片、簽名、畫筆…)依原本的前後順序一起燒進影像,被蓋住的部分不會重新出現;塗黑之後才加的標註照常畫在上面。

## 3. 已知限制

- 改字:原文字會刪掉,但新文字是另外加上的文字標註,**不會和同一行的其他字重新排版**(新內容比較長時可能蓋到後面的字,要自己移動);新文字用內嵌的思源黑體(明體、楷體是圖片),和原本的字型不同;只支援畫面上水平的文字(直書、斜的文字只能框選蓋掉);原字型的字形資料仍在檔案裡(只刪文字,不重做字型子集);表單欄位與註解裡的文字不處理。
- 加入的文字:只有「黑體」會寫成真文字(內嵌字型只有思源黑體 Regular 一種);明體、楷體與思源黑體缺少的字(Big5 罕用字約 3,600 個、擴充區漢字)以圖片嵌入,無法選取/搜尋。粗體是描邊加粗,不是真正的粗體字型。浮水印與頁碼仍是圖片。內嵌字型與 fontkit 讓兩個版本的 HTML 各多約 3.5 MB(精簡版約 6.4 MB)。
- 被「真塗黑」轉影像的頁面,文字不可選取。
- 有密碼的 PDF:開啟後匯出的檔案不再沿用原本的密碼(可在匯出時另外設定);憑證加密(Public-Key security handler)與非標準的加密外掛無法開啟;只用 pypdf 與 qpdf 產生的檔案測試過。
- 填寫表單:填寫的值不在復原/重做(Ctrl+Z)範圍內;擷取文字、Word 等輸出不包含欄位的值;中文值的外觀是圖片(轉成一般內容後無法選取搜尋);不支援簽章欄位、按鈕、欄位的計算與格式化腳本(JavaScript)、XFA 表單(填寫時移除 XFA,改用一般表單)、旋轉的欄位(/MK /R);合併多個有表單的檔案時,同名欄位不會自動改名。
- 移除浮水印:印在掃描影像裡、或畫成一般向量圖形(沒有文字、不透明也沒有旋轉)的浮水印無法辨認;規則判斷可能漏掉或誤判,所以一律列出讓使用者確認。移除不在復原/重做(Ctrl+Z)範圍內,要恢復請在同一個視窗取消勾選再套用。請只用在你有權處理的文件上。
- 文字辨識(OCR):清楚的印刷文件錯字率約 1%,掃描與傳真約 3–4%(M3 測試集);低解析度模糊的掃描會漏掉筆畫少的字(一、二、日);偶爾輸出簡體字(已自動轉成繁體,但「后、里、干、面、么」等繁體也用的字不會轉,例如「里面」「干净」會變成「里面」「干淨」);手寫、印章、直書沒有測試;每頁約 3–5 秒(單執行緒,`file://` 下無法多執行緒);辨識一頁 A4 約再用 1 GB 記憶體。精簡版沒有內建 OCR,要辨識時每次開啟都要重新載入 OCR 套件檔。
- 可搜尋 PDF:同一段(不需要空格的連續字詞)內的字平均分配寬度,中英數混排時選取範圍可能與原圖的字略有偏差;直書沒有測試。只用 pdfium(Chrome)、pypdf、pdf.js 驗證過,Adobe Acrobat 與 macOS 預覽程式未測。
- 裁切:只設定可見範圍(CropBox),**裁掉的內容仍在檔案裡**(用其他程式取消裁切或擷取文字就看得到),要移除敏感內容請用塗黑;擷取文字、Word/Markdown/Excel 匯出不套用裁切。
- 壓縮 PDF:只處理 8 位元 RGB/灰階的 JPEG 與 Flate 圖片;CMYK、索引色、色彩鍵遮罩、JPEG 2000、黑白傳真格式(CCITT/JBIG2)、註解外觀裡的圖片不動;字型不做子集化,以文字為主的檔案幾乎不會變小;灰階圖片會存成彩色 JPEG。
- 匯出時加密碼:只提供 AES-256(很舊的閱讀程式,例如 Acrobat 9 以前,打不開);權限限制(禁止列印、複製…)要靠閱讀程式遵守,不能防止有心人破解,只有開啟密碼才真正保護內容;只用 pypdf、pdfium(Chrome)、qpdf 驗證過,Adobe Acrobat 與 macOS 預覽程式未測。
- 匯出 Excel:只匯出偵測到的表格(表格以外的文字不放);公式、日期型別、跨頁的同一個表格(會變成兩個工作表)不處理。
- 匯出 Word:沒有框線、欄位又都是長句的表格仍會當成分欄;數學式、文繞圖、直書、複雜多欄只能近似(多欄會依閱讀順序排成單欄);文字顏色與底線沒有保留(表格深色底色上的字改用白色);向量圖以 150 dpi 圖片呈現,圖上文字無法編輯;頁首文字不會放進 Word 頁首(只移除)。
- 擷取文字:與塗黑框有任何重疊的文字片段會整段排除(一段可能是一整行),表格與直書的閱讀順序可能不正確;在頁面上框選文字時,要從文字上開始拖曳(從空白處開始不會選取);透明文字層依版面分析的閱讀順序排列,並使用 PDF 內嵌的字型(沒有內嵌字型時用一般無襯線字型,行尾可能略有偏差)。
- 分欄:側欄與正文剛好在同一高度對齊的小方框(例如正文旁的「Contents」)不會被當成表格,可能接成一段。
- 只測過 Chromium(headless,觸控用 Chrome 的觸控事件模擬);Safari 與實體平板未測。觸控時用繪圖工具不能在頁面上捲動(先切回「選取」再捲動)。
- 在 Claude.ai 的預覽沙盒(claudeusercontent.com)中,建立 blob Worker 會被瀏覽器擋下,主控台會出現 `worker fallback SecurityError` 警告;程式已自動退回主執行緒,**無害**。從本機 `file://` 開啟則不會出現。

### 4.1 檔案配置

```
pdf-workbench/
├── build.py          # 把函式庫/worker/CMap/app 全部內嵌成單一 HTML;--ocr 另外內嵌文字辨識引擎與模型
├── package.json      # 只用來 npm install 取得函式庫(版本已鎖定)
├── package-lock.json

├── docs/OCR_SPIKE.md # OCR 引擎比較(M3)
├── spike/ocr/        # M3 的比較原型與測試集(不屬於正式建置)
├── CLAUDE.md        # 給 Claude 的專案規則(溝通語言、流程、架構與塗黑安全規則)
├── requirements-dev.txt   # 測試用 Python 套件
├── .github/workflows/test.yml   # CI:建置 + 測試,並上傳建置好的 HTML
├── src/
│   ├── app.html      # HTML + CSS 模板,含 /*__PDFLIB__*/ 等佔位符
│   ├── ocr/worker.js # OCR 的背景 Worker(偵測、裁切、辨識;不在 MODULES 內,--ocr 時與 onnxruntime 串成 Blob Worker)
│   └── js/           # 應用邏輯(無框架、純 JS),依 build.py 的 MODULES 順序串接

│       ├── ui/       # feedback、main-view、thumbs、navigation、page-ops、toolbar、pointer、對話框
│       ├── text/     # 文字擷取、版面分析、表格偵測
```

**模組規則**:所有模組串接進同一個 `<script>`,共用同一個全域範圍(沒有 import/export)。新增檔案時要加到 `build.py` 的 `MODULES`,順序就是相依順序;`MODULES` 與 `src/js/` 內容不一致時建置會直接失敗。

### 4.2 資料模型

```js
S.pages = [{ uid, src, idx, r, w, h, R0, anns: [...] }]
```
- `src`:來源檔 id(`sources` Map:`{name, bytes, doc(pdf.js), lib(pdf-lib)}`)
- `idx`:來源檔內的頁索引
- `r`:使用者額外旋轉(0/90/180/270)
- `w, h`:頁面**基準尺寸**(pt),取自 `page.getViewport({scale:1})`(已含 PDF 本身的 `/Rotate`)
- `R0`:PDF 本身的內建旋轉(`page.rotate`)
- `anns`:標註陣列,型別 `pen | line | hl | redact | img | text | crop | erase`(`erase` = 改字框)
- 圖片與文字圖存在 `assets` Map(id → bytes/mime/objectURL),標註只存 asset id,所以 undo 快照是輕量的 `JSON.stringify(S.pages)`。

### 4.3 座標系統(最容易出錯的地方)

- **所有標註都存在「基準座標」**:頁面原始方向、單位 pt、原點在左上、y 向下。
- 使用者的旋轉 `r` **只是顯示時的 CSS `rotate()`**(`.pvin` 內層容器),所以旋轉頁面時標註會自動跟著轉,不用改標註資料。
- 滑鼠座標 → 基準座標:先取外層 `.pv`(未旋轉)的 `getBoundingClientRect`,得到顯示座標 `(dx,dy)`,再用 `dispToBase(dx,dy,e)` 逆轉換。`baseToDisp` 為反向。
- 匯出時,基準座標 → PDF 使用者空間座標:用 pdf.js 的 `viewport.convertToPdfPoint(bx,by)`,它已處理 CropBox 與內建 `/Rotate`。pdf-lib 頁面則 `setRotation(degrees((R0 + r) % 360))`。
- 圖片類標註在匯出時取左下角與右下角兩點轉換,用 `atan2` 算出旋轉角,所以任意旋轉都正確。
- 螢光筆與塗黑用「粗直線」畫(`drawLine`,`thickness = 矩形高度`),避免旋轉時矩形變形;螢光筆用 `BlendMode.Multiply`。
- 真塗黑的頁面:用 pdf.js 以 `rotation = R0 + r` 直接渲染成顯示方向影像,再把 canvas 設成「基準座標 → 影像像素」的仿射轉換(由 `baseToDisp` 算出),依序燒入最後一個塗黑框以前的所有標註(`burnAnn`);新頁面無旋轉,其餘標註的映射函式改為 `(bx,by) → baseToDisp → (x, dh - y)`。

### 4.4 畫面渲染

- 主區:每頁一個 `.pv`,內含 `<canvas>`(pdf.js 渲染,基準方向)與 `<svg>`(標註,viewBox = 基準尺寸)。三個 `<g>`:`.ga` 標註、`.gm` 浮水印/頁碼預覽、`.gs` 選取框與縮放把手。
- `syncMain()` / `syncThumbs()` 以 uid 做 diff,只增刪、重排、改尺寸,不重建 DOM;縮放時才重新渲染 canvas。
- 渲染有並行上限(`withSlot`,最多 3 個),單一 canvas 上限 1600 萬像素。
- 文字/浮水印/頁碼都由 `renderTextAsset()` 用 canvas 畫成 PNG(放大 K 倍保持清晰)。

### 4.5 離線注意事項

- pdf.js worker:`URL.createObjectURL(new Blob([b64ToU8(WORKER_B64)]))`,並嘗試 `new Worker(url)` 設成 `workerPort`;失敗則退回 fake worker。
- CMap:自訂 `InlineCMapFactory`(`fetch({name})` 回傳 `{cMapData, compressionType:1}`),傳給 `getDocument({CMapReaderFactory})`。
- 內嵌進 `<script>` 的程式碼,`build.py` 會把 `</script` 換成 `<\/script` 並移除 sourceMappingURL。
- ZIP 為自寫的「僅儲存不壓縮」實作(含 CRC32、UTF-8 檔名旗標)。

## 5. 建置與執行

需求:Node.js(只為了下載函式庫)、Python 3。

```bash
npm ci               # 依 package-lock.json 安裝 pdf-lib、@pdf-lib/fontkit、pdfjs-dist@3.11.174、onnxruntime-web、PP-OCRv5 模型、思源黑體
npm run build        # 等同 python3 build.py,輸出精簡版 dist/pdf-workbench.html
python3 build.py --ocr   # 完整版 dist/pdf-workbench-ocr.html(需要 pip install -r requirements-dev.txt 的 onnxruntime)
# 或指定輸出路徑:python3 build.py /path/to/out.html [--ocr]
```

- 兩個版本都內嵌思源黑體:把 `@fontsource/noto-sans-tc` 的 Regular 分片(約 110 個 WOFF2)用 fonttools 合併成一個字型(去掉排版表與 hinting,字形補齊到 4 bytes 給 fontkit 做子集),結果快取在 `node_modules/.cache/` 並核對 SHA-256;需要 `requirements-dev.txt` 的 fonttools 與 brotli。授權(SIL OFL 1.1)全文放在 HTML 的註解裡。
- `--ocr` 會把辨識模型的 MatMul 權重量化成 int8(準確度不變、小 7 MB),結果快取在 `node_modules/.cache/` 並核對 SHA-256;onnxruntime/onnx 版本不同會得到不同的檔案,建置會停止並提示。

- 建置後用瀏覽器直接開 `dist/pdf-workbench.html`(`file://`)即可,不需要 web server。
- **不要升級 pdfjs-dist 到 4.x 以上**:新版只有 ES module,無法用 `<script>` 內嵌成單檔,`build.py` 與 `openWithPdfJs` 的選項也要跟著改。
- **`openWithPdfJs` 必須保留 `isEvalSupported: false`**:pdf.js ≤ 4.1.392 有 CVE-2024-4367(惡意 PDF 的字型可執行任意 JS),因為版本無法升級,只能靠這個選項緩解。

### 發布新版本

發布流程在 `.github/workflows/release.yml`:先跑完整測試,通過後才建立 GitHub Release,並附上 `pdf-workbench.html`、`pdf-workbench-ocr.html` 與 `pdf-workbench-ocr-pack.bin`;接著把最新版與下載頁(`.github/pages/make_index.py` 產生)部署到 GitHub Pages(專案 Settings → Pages 的 Source 要設成「GitHub Actions」)。Pages 的下載通常比 Releases 快,HTML 也會以壓縮傳輸。

- **網頁操作**:GitHub → Actions → **release** → Run workflow → 輸入版本號(例如 `v0.2.0`)
- **命令列**:`git tag v0.2.0 && git push origin v0.2.0`

版本號格式為 `vX.Y.Z`:修正錯誤加 Z、新增功能加 Y。發布內容說明會依合併的 PR 自動產生。附件名稱固定,`https://github.com/tony028p/pdf-workbench/releases/latest/download/<檔名>` 永遠指向最新版本。

## 6. 測試

```bash
pip install -r requirements-dev.txt
python -m playwright install chromium       # 已有對應版本的 Chromium 可略過,或用 CHROMIUM_PATH 指定執行檔
npm test                                     # 等同 python3 -m pytest
```

- 測試會自行建置精簡版與完整版 HTML 到暫存目錄(不動 `dist/`),以 Playwright + Chromium 無頭模式從 `file://` 開啟,用滑鼠事件操作,匯出後用 `pypdfium2` / `pypdf` 驗證。
- **每個測試都會自動檢查**:沒有未捕捉的 JS 錯誤、沒有任何對外網路請求(離線承諾;頁面與 Worker 的請求都會檢查)。
- 每次 push 與 PR 都會在 GitHub Actions 執行,並把建置好的兩個 HTML 上傳成可下載的 artifact。
